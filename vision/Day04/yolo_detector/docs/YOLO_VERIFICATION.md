# 검증 결과

검증일: 2026-09-23

- ROS 2 Jazzy 패키지 빌드 성공.
- 실제 첨부 모델을 PyTorch CPU로 불러와 객체 사진에서 사람과 버스 탐지 확인.
- 카메라 노드 → 이미지 토픽 → 추론 노드 → 결과 토픽 전체 Launch 테스트 성공.
- 전체 클래스: 사람과 버스가 출력됨.
- 클래스 `[0]` 선택: 사람만 출력됨.
- confidence `0.99999`: 같은 테스트 영상에서 빈 탐지 목록 출력.
- 클래스 ID와 이름이 불일치하면 오류로 거부됨.
- 원본 이미지 좌표 범위, 이미지 크기·인코딩, 원본 header 전달 확인.
- 동일 프레임 중복 추론 없이 새 프레임의 결과가 발행되는 것을 확인.
- 실제 카메라 0에서 결과 8프레임 수신. 결과 크기 640×480.
- 실제 결과 창 생성 로그 확인. GUI의 시각적 배치는 별도 스크린샷으로 검수하지 않음.
- 카메라 검증의 마지막 프레임 predict 처리 시간 약 33.2ms. 평균 성능이나 다른 PC에서의 속도 보장 수치가 아님.
- SIGINT 종료 시 두 노드 정상 종료, 자원 정리 중 중복 신호 오류 수정 후 재검증.
- 테스트 후 카메라 프로세스 종료. 실제 카메라 영상 저장 없음.

사용 버전: Python 3.12, torch 2.14.0+cpu, torchvision 0.29.0+cpu, ultralytics 8.4.160, numpy 1.26.4, opencv-python 4.11.0.86.

## 끊김 개선 후 재검증

사용자가 10 FPS 미만의 끊김을 보고하여 실제 카메라로 원인을 분리 측정했습니다.

- 직접 카메라 읽기: 버퍼 1개에서 약 15.4 FPS, 2개에서 약 30.0 FPS.
- 기존 ROS 파이프라인(8초 측정): 관측 입력 약 7.7 FPS, 탐지 약 6.6 FPS.
- 카메라 버퍼 2개, 촬영 스레드 분리, 추론 스레드 분리, 추론 목표 30 Hz로 수정.
- 영상 미리보기는 추론과 독립적으로 최신 카메라 프레임을 표시.
- 최종 실제 창 표시 테스트(8초): 탐지 결과 수신 약 23.8 FPS, predict 시간 중앙값 약 36.0ms.
- 최종 시점의 최근 30프레임 내부 집계: 수신 29.1 FPS, 추론 23.9 FPS, 화면 갱신 26.9 FPS.
- 외부 확인 노드의 원본 이미지 수신 약 26.0 FPS, 결과 이미지 수신 약 19.5 FPS. 큰 Image 메시지를 추가 구독하는 관측기의 FPS와 실제 창 갱신 FPS는 다릅니다.
- 입력 크기 640 및 confidence 0.5 유지. 실행 조건에 따라 FPS는 달라질 수 있습니다.
- 일상 클래스 30개의 ID와 이름을 포함된 모델 이름표와 대조하여 일치 확인. 기본 설정에서 이 목록을 사용하도록 설정.
- 실제 카메라와 GUI 테스트 후 두 노드의 정상 종료 확인. 영상 저장 없음.
